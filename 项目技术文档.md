## 1. 项目概述

### 1.1 项目简介

WhisperLiveKit 是一个基于 OpenAI Whisper 的**超低延迟、自托管**实时语音转文字系统，具备说话人识别、多语言翻译、唤醒词检测等功能。系统采用前后端分离架构，通过 WebSocket 实现音频流的实时传输与处理，支持 Docker 容器化部署。

### 1.2 核心特性

| 特性      | 说明                                             |
| ------- | ---------------------------------------------- |
| 实时转录    | 亚秒级延迟，支持 Simul-Streaming 和 LocalAgreement 两种策略 |
| 说话人识别   | 集成 Diart 和 Sortformer，实时区分多个说话人                |
| 多语言翻译   | 基于 NLLB 模型，支持 200+ 语言实时翻译                      |
| 唤醒词检测   | 基于 sherpa-onnx / Zipformer，低功耗本地检测             |
| 中文优化    | 集成 OpenCC 繁简转换，支持中文专业术语关键词                     |
| 会议管理    | 完整的会议录音归档、转录编辑与回放功能                            |
| 管理后台    | 可视化配置、关键词管理、唤醒词管理                              |
| Web SDK | 可集成到第三方网页的 JavaScript SDK                      |
| 多部署模式   | 支持本地运行、CPU Docker、GPU Docker、Nginx 反向代理        |

### 1.3 技术栈总览

- **后端**：Python 3.9+、FastAPI、Uvicorn、SQLite
- **前端**：原生 HTML/CSS/JavaScript（无框架依赖）
- **AI 模型**：faster-whisper、Silero VAD、Sortformer/Diart、sherpa-onnx
- **音频处理**：FFmpeg、NumPy、PyTorch
- **部署**：Docker、Docker Compose、Nginx

### 2.2 请求生命周期

**实时转录流程：**

```
浏览器麦克风
  → MediaRecorder / AudioWorklet 采集音频
  → WebSocket 二进制帧发送到 /asr
  → AudioProcessor.process_audio() 接收
  → FFmpegManager 转码（非PCM格式）/ 直接写入PCM缓冲
  → Silero VAD 语音活动检测
  → 音频数据入队 transcription_queue / diarization_queue
  → TranscriptionEngine 并行处理（转录 + 说话人识别 + 翻译）
  → TokensAlignment 对齐合并结果
  → results_formatter() 生成 FrontData 响应
  → WebSocket 发回 JSON 给浏览器
  → 前端 renderLinesWithBuffer() 更新 DOM
```

## 3. 功能模块详解

### 3.1 实时转录

#### 两种转录策略

| 策略              | 参数值              | 原理                          | 适用场景   |
| --------------- | ---------------- | --------------------------- | ------ |
| Simul-Streaming | `simulstreaming` | AlignAtt 对齐头预测单词边界，流式输出部分结果 | 超低延迟需求 |
| LocalAgreement  | `localagreement` | 多帧结果局部一致性投票，稳定后输出           | 高准确率需求 |

#### 支持的后端

- `faster-whisper`：基于 CTranslate2 的高效 Whisper 实现（默认）
- `mlx-whisper`：Apple Silicon 优化版本
- `openai-whisper`：原版 OpenAI Whisper

#### 关键参数

| 参数                      | 说明                                | 默认值    |
| ----------------------- | --------------------------------- | ------ |
| `model`                 | 模型大小：tiny/base/small/medium/large | `tiny` |
| `language`              | 识别语言，`zh` 为中文                     | `zh`   |
| `min_chunk_size`        | 最小音频块大小（秒）                        | `0.15` |
| `buffer_trimming_sec`   | 缓冲区修剪阈值（秒）                        | `10.0` |
| `beam_size`             | Beam Search 宽度，越大越准但越慢            | `2`    |
| `confidence_validation` | 置信度过滤低质量结果                        | `true` |
| `punctuation_split`     | 按标点符号分割转录行                        | `true` |

### 3.2 语音活动检测（VAD）

使用 **Silero VAD**（内置 ONNX/JIT 模型），主要作用：

1. 实时检测音频中的语音起止点
2. 只对含语音的片段进行转录，节省计算资源
3. 生成 `Silence` 对象，携带静音段时长信息，供转录引擎处理停顿

### 3.3 说话人识别（Diarization）

两种说话人识别方案：

**Sortformer（推荐）**

- 模型：`nvidia/diar_streaming_sortformer_4spk-v2`
- 特点：NVIDIA 流式方案，最多4路说话人，准确率高
- 通过 NeMo 框架加载

**Diart**

- 基于 pyannote/segmentation + SpeechBrain ECAPA
- 滑窗实时处理，适合长时会议

开启条件：配置 `diarization: true` 并提供模型路径。

### 3.4 唤醒词检测

#### 工作原理

```
持续监听麦克风（16kHz PCM）
  → 音频分块（帧级处理）
  → sherpa-onnx Zipformer KWS 模型推理
  → 置信度 ≥ threshold（默认 0.6）
  → WebSocket 发送 wakeword_detected 事件
  → 前端切换到转录模式
  → 用户停止说话超过 timeout 后自动结束
  → 恢复唤醒词监听
```

#### 核心组件

| 组件                  | 文件                          | 说明                                        |
| ------------------- | --------------------------- | ----------------------------------------- |
| `HotwordService`    | `hotword_service.py`        | 管理 sherpa-onnx KWS 流，每个 WebSocket 连接独立一个流 |
| `HotwordDetector`   | `hotword_detector.py`       | 封装 sherpa-onnx 推理逻辑                       |
| `WakewordsManager`  | `wakewords_manager.py`      | 唤醒词列表的增删改，写入模型目录                          |
| `WhisperHotword.js` | `web/sdk/WhisperHotword.js` | 前端 SDK，封装唤醒词监听和自动转录切换                     |

#### 配置参数

```json
{
  "hotword_model_dir": "/app/models/sherpa-onnx-kws-zipformer-wenetspeech",
  "hotword_threshold": 0.6,
  "hotword_sample_rate": 16000,
  "hotword_threads": 4
}
```

### 3.5 多语言翻译

- 模型：NLLB（No Language Left Behind）基于 `nllw` 包
- 触发方式：启动时指定 `--task translate` 或在配置中开启
- 输出：每行转录结果附带翻译文本，前端单独渲染

### 3.6 中文专业术语支持

`KeywordsManager` 维护 `keywords.txt` 文件，在转录后对结果进行关键词替换，提升专业术语识别准确率。支持通过管理后台动态增删改，无需重启服务。

## 4. 后端技术实现

### 4.1 技术栈

| 组件             | 版本/说明                                |
| -------------- | ------------------------------------ |
| Python         | 3.9 - 3.15                           |
| FastAPI        | 最新稳定版                                |
| Uvicorn        | ASGI 服务器                             |
| faster-whisper | ≥ 1.2.0                              |
| PyTorch        | CPU: 2.10.0 / GPU: 2.8.0 (CUDA 12.9) |
| sherpa-onnx    | 唤醒词检测                                |
| NeMo (ASR)     | 说话人识别（本地源码安装）                        |
| SQLite         | 轻量级会议记录存储                            |
| python-jose    | JWT 令牌生成与验证                          |
| passlib        | 密码哈希（pbkdf2\_sha256）                 |
| OpenCC         | 中文繁简转换                               |

### 4.2 服务启动流程

```python
# basic_server.py 启动流程
lifespan() 启动
  → config_manager.get_config()  读取 config.json
  → 用命令行参数 + 配置文件参数初始化 args
  → reload_services()
      ├── TranscriptionEngine(**vars(args))  加载 AI 模型（耗时操作）
      ├── KeywordsManager(keywords_file)
      ├── HotwordService(model_dir, ...)     若配置了唤醒词模型
      └── WakewordsManager(hotword_model_dir)
  → 注册 SIGHUP / SIGUSR1 热重载信号（Linux）
  → Uvicorn 开始监听端口
```

### 4.3 WebSocket 连接管理

**转录连接** **`/asr`：**
每个 WebSocket 连接创建一个独立的 `AudioProcessor` 实例，互不干扰，天然支持多用户并发。

**唤醒词连接** **`/hotword`：**
`HotwordService` 维护一个 `connection_id → KWS流` 的字典，连接断开时自动释放流资源。

### 4.4 热重载机制

通过 `POST /api/config/restart` 或发送 SIGHUP 信号触发，无需重启进程：

1. 重新读取 `config.json`
2. 在独立线程中重新初始化 `TranscriptionEngine`（重新加载模型）
3. 更新全局服务引用
4. 等待最多 60 秒，返回成功/失败/超时状态

### 4.5 CORS 配置

开发阶段允许所有来源（`allow_origins=["*"]`）。生产环境建议通过 Nginx 层面限制来源，并关闭 CORS 宽松配置。

### 4.6 SSL / HTTPS 支持

启动时指定 `--ssl-certfile` 和 `--ssl-keyfile`，Uvicorn 将以 HTTPS/WSS 模式启动。Docker 部署时通过 Nginx 统一处理 SSL 终止更为推荐。

### 5.4 会议管理系统（Meeting）

三个页面组成完整会议管理流程：

```
meeting_home.html      会议列表
  → 点击「新建会议」  → meeting_transcription.html  实时转录 + 归档
  → 点击「查看详情」  → meeting_detail.html          回放 + 编辑转录
```

**数据保存流程（meeting\_transcription.html）：**

1. 启动实时转录，同时录制完整音频（MediaRecorder 录制到 Blob）
2. 用户点击「保存」，弹出命名对话框

**会议详情（meeting\_detail.html）：**

- 音频播放器回放录音
- 可编辑每条转录记录的文本、说话人、时间戳
- `PATCH /api/meetings/{id}` 同步编辑到数据库

## 6. API 接口文档

### 6.1 WebSocket 接口

#### `ws[s]://host/asr` — 实时转录

**连接建立后，服务端发送配置：**

```json
{"type": "config", "useAudioWorklet": true}
```

**客户端发送：**

- 二进制帧：PCM Float32 音频数据（useAudioWorklet=true）或 WebM 音频
- 空二进制帧：发送停止信号

**服务端响应（实时推送）：**

```json
{
  "status": "active_transcription",
  "lines": [
    {
      "speaker": 1,
      "text": "你好，欢迎使用实时转录系统",
      "start": 0.0,
      "end": 2.5,
      "detected_language": "zh",
      "translation": ""
    }
  ],
  "buffer_transcription": "正在处理...",
  "buffer_diarization": "",
  "buffer_translation": "",
  "remaining_time_transcription": 0.12,
  "remaining_time_diarization": 0.35
}
```

**status 枚举值：**

| 值                      | 含义       |
| ---------------------- | -------- |
| `active_transcription` | 正在转录     |
| `no_audio_detected`    | 未检测到音频输入 |
| `finalizing`           | 处理最后一段音频 |

**处理完毕信号：**

```json
{"type": "ready_to_stop"}
```

***

#### `ws[s]://host/hotword` — 唤醒词检测

**连接建立后，服务端发送配置：**

```json
{
  "type": "config",
  "connection_id": "a1b2c3d4",
  "sample_rate": 16000,
  "threshold": 0.6,
  "useAudioWorklet": true
}
```

**客户端发送：** 二进制 PCM 音频帧（16kHz）

**服务端响应（检测到唤醒词时）：**

```json
{
  "type": "wakeword_detected",
  "wakeword": "小爱同学",
  "timestamp": 1743494400.123
}
```

## 8. 认证与授权

### 认证流程

```
POST /api/auth/login  (username + password)
  → UserManager.authenticate_user()
      ├── 读取 users.json 查找用户
      ├── pbkdf2_sha256 验证密码
      └── 检查 disabled 状态
  → create_access_token()  生成 JWT（HS256，30分钟有效期）
  → 返回 {"access_token": "...", "token_type": "bearer"}

后续请求
  → Header: Authorization: Bearer <token>
  → get_current_active_user() 验证 JWT
  → 解码 payload 获取 username
  → 再次查询 users.json 确认用户存在且未禁用
```

### 安全说明

> **注意**：`SECRET_KEY` 硬编码在 `auth.py` 中，生产部署前必须通过环境变量注入自定义密钥。

```python
# 生产环境建议修改为：
SECRET_KEY = os.getenv("JWT_SECRET_KEY", "fallback-only-for-dev")
```

```nginx
location / {

    proxy_set_header Connection "upgrade";
    proxy_read_timeout 86400;   # WebSocket 长连接超时
    proxy_send_timeout 86400;
}
```

**启用 HTTPS：** 取消 nginx.conf 中 HTTPS server 块的注释，配置证书路径：

```nginx
server {

}
```

### 10.6 Dockerfile 构建层说明

以 `Dockerfile.cpu` 为例，构建分层设计充分利用 Docker 缓存：

```dockerfile
# 层1：系统依赖（变动最少）
RUN apt-get install ffmpeg git portaudio19-dev ...

# 层2：PyTorch（大包，优先缓存）
RUN pip install torch==2.10.0 torchaudio==2.10.0 --index-url .../cpu

# 层3：NeMo（本地源码安装）
COPY NeMo /app/NeMo

COPY . .
RUN pip install -e .[chinese_conversion]

RUN pip install sherpa-onnx opencc-python-reimplemented

# 启动命令
ENTRYPOINT ["whisperlivekit-server", "--host", "0.0.0.0"]
CMD ["--model", "tiny"]
```

> **提示**：国内环境使用阿里云/清华镜像加速，PIP 超时设置为 1000 秒，避免大包下载失败。
